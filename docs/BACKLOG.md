# Backlog — recommendations & follow-ups

A living list of improvements and ideas noted during development. Not part of the
committed 4-plan scope; pull items from here into a future plan when prioritized.

Status: 🔵 idea · 🟡 planned · 🟢 done

| # | Area | Recommendation | Why | Status |
|---|------|----------------|-----|--------|
| 1 | Admin / Blog UX | Auto-generate the **slug** from the title (e.g. "Blog article 1" → `blog-article-1`), still allowing manual override. Slug-ify per locale. | Right now the slug is a manual field; leaving it blank produces a post with no working URL. Auto-fill removes a common foot-gun. | 🔵 idea |
| 2 | Admin / Blog UX | Auto-derive **excerpt** from the first ~160 chars of the body when left empty. | Saves editors a step; ensures the blog list always has a teaser. | 🔵 idea |
| 3 | Security | Add optional **2FA** for admin login (noted as "later" in the spec). | Stronger admin account protection. | 🔵 idea |
| 4 | Admin / Editor | Premium CKEditor features (Import from Word, Export PDF/Word, CKBox, merge fields, AI, comments/track-changes) are **paid** and excluded. Revisit only if a real need + budget appears. | Sets expectations vs. the CKEditor marketing demo. | 🔵 idea |
| 5 | Theme / UX | Dead links when a section is toggled off — fixed 2026-08-01. The Home page rendered its "Learn More" button (`/{locale}/about`) and the entire "From the Journal" block regardless of the `about`/`blog` toggles, so both 404'd; nav, footer, About and Services were already guarded. Home's blocks now check `sectionVisible()` and `PageController::home()` returns no posts when `blog` is off, skipping the query. The hero CTA needed more than an `@if`, since `cta_url` is free-form admin input: themes now read `SiteSetting::heroFor($locale)`, which drops a CTA whose target section is hidden (label included) and rewrites the URL's locale segment, fixing a second bug where a `/ro` visitor was sent to `/en` pages. Off-site URLs pass through. | A CTA into a disabled section is a 404 the admin never sees; the guard now lives in one place every theme inherits. | 🟢 done |
| 6 | Maintenance | Bump `phpunit/phpunit` `^11.0.1` → `^12.5` — done 2026-08-01 (locked 12.5.33), the version Laravel 13's upgrade guide names. No third-party blocker: only phpunit-family and `sebastian/*` transitives moved, and `nunomaduro/collision` 8.9.4 declares `conflict: phpunit/phpunit <11.5.50 \|\| >=14.0.0`, so it already covered 12. No test or config change was needed — `phpunit.xml` was already on the 10+ schema (`<source>`, no `<coverage>` block) and no test used doc-comment metadata or APIs removed in 12. Suite runs 271/271 with zero deprecations, notices or warnings. PHPUnit **13** stays out of reach until local dev PHP moves to ≥ 8.4.1 (currently 8.3.31); CI and the host are already on 8.4. | Stay on the version Laravel tests against, while the migration cost is still zero. | 🟢 done |
| 7 | Deployment | Confirm prod serves after the cPanel PHP pin — confirmed 2026-08-01. `astrotherapia.com` and `astrotherapia.ro` had been on **PHP 8.1**, inherited from the system default, which is below Laravel 12's `^8.2` floor; both are now pinned to **8.4** explicitly and verified serving. Keep them pinned rather than on *inherit* — the system default is still 8.1. Extensions are per PHP version, so if anything image- or locale-related misbehaves, check the 8.4 extension set against [`docs/DEPLOY-CPANEL.md`](DEPLOY-CPANEL.md) first. | A silently broken prod domain looks identical to one that was never launched. | 🟢 done |
| 8 | Maintenance | Upgrade to **Laravel 13** — done 2026-08-01 (`^13.0`, locked 13.23.0), together with `laravel/tinker` `^3.0` (2.x capped at illuminate `^12` and was the only blocker) and `intervention/image` `^4.2`. No app code changed: the guide's high/medium-impact items don't apply here (no `VerifyCsrfToken`/`withoutMiddleware` references, no `upsert`, no cache or queue usage, no `array_first`/`array_last` helpers, and `config/cache.php`/`config/session.php` already define the prefix and cookie name so the renamed framework fallbacks never fire). Adopted the new `cache.serializable_classes => false` default. All 271 tests pass unchanged. | Avoided a future double-major jump; done deliberately with a clean `composer audit`, not under advisory pressure. | 🟢 done |
| 9 | Security / maintenance | Upgrade off the flagged Laravel 11 line — done 2026-07-08 by moving to **Laravel 12** (`^12.0`, locked 12.63.0), clearing three advisories with no patched 11.x release (notably CVE-2026-48019, CRLF injection in the default `email` rule, reachable from the contact form). `composer audit --no-dev` is a **blocking** CI gate. | Dependencies off a flagged version; regressions now fail the pipeline instead of shipping. | 🟢 done |
| 10 | Repo hygiene | Drop the stale `config.policy.advisories.block: false` override from `composer.json` — a leftover from the Laravel 11 era. | Re-arms Composer's install-time advisory guard, so a flagged package fails locally at `composer require` instead of only in CI. | 🟢 done |
| 11 | Repo hygiene | Remove unused **Node frontend scaffolding** (`package.json`, `vite.config.js`, `tailwind.config.js`, `postcss.config.js`, `resources/js`, `resources/css`) shipped by the Laravel scaffold. Also removed the unrouted `welcome.blade.php` (sole `@vite` consumer), the ported-away `resources/theme_solarsystem/` reference, and de-Noded the `composer.json` `dev` script. | The project is intentionally Node-free (plain CSS). These files were dead weight and could mislead. | 🟢 done |
| 12 | Admin / Editor | CKEditor is **self-hosted** from the npm package's `dist/browser/ckeditor5.umd.js` (distribution channel `"sh"`), valid with the GPL key — no CDN, no Node build. When upgrading CKEditor, re-pull the `dist/browser/` UMD from the npm tarball, not the CDN. | Earlier attempts failed: the GPL key is invalid on the CDN/"cloud" build. Records the constraint so a future upgrade doesn't regress to the CDN. | 🟢 done |
| 13 | Payments | **Payments (Plan 3) is written but not built.** The spec/plan pair (`PaymentProvider` abstraction + a Stripe implementation) sits at [`docs/superpowers/plans/2026-06-25-reusable-site-template-php-payments.md`](superpowers/plans/2026-06-25-reusable-site-template-php-payments.md); no payment code exists in the app. | The plan file's existence reads as "shipped" to anyone skimming the folder. Records that it is the one unbuilt plan of the original four (Foundation, Admin+Blog and Deployment are all live). | 🟡 planned |
| 14 | Theming | The retired **`mystik`** token set was **archived rather than repackaged** — 2026-08-01. Analysis showed there was nothing to package: mystik never had CSS of its own, it re-skinned the then-shared `public/css/{structure,skin}.css` (which *became* `theme_default/css/`) with 11 token overrides, and Solar System superseded the look. So `public/fonts/eb-garamond-{400,700,400-italic}.woff2` — its last trace, referenced by nothing — was deleted, and `public/fonts/` with it. The rule that made mystik an outlier is now enforced instead of documented: `tests/Unit/ThemeSelfContainmentTest.php` fails on any font binary under `public/` outside a `themes/theme_<name>/` folder (`vendor/`, `storage/` exempt). **To revive it**, nothing needs porting — take the token set verbatim from `git show 9db3bbc^:config/themes.php` (`themes.mystik`: `#0a0a0f` bg, `#f0a23c` gold heading/primary, Cinzel display, EB Garamond base), clone `theme_default/` and re-map, remembering the registry has since grown `font-heading`, `color-footer-bg`/`-fg`, `color-gold`, which mystik's 11 tokens never set. Its starfield hero and gold wordmark nav are at `git show 3b4b40d^:resources/views/partials/hero.blade.php`; the design spec/plan pair stays in `docs/superpowers/`. | Every theme is now self-contained, and the stray fonts are gone rather than adopted by a theme nobody would select. | 🟢 done |

## How to use this file
- Add a row whenever a "nice-to-have" or recommendation surfaces mid-build.
- Keep entries short; the *Why* column is the value, not the implementation detail.
- When an item is scheduled, write a spec/plan for it and flip status to 🟡, then 🟢 when shipped.
